# DEVKIT — 项目开发规范「一键初始化」指南（给 LLM 的单文件）

> **用途**：你在任何一个新项目里读到本文件（或探测到项目未经本规范初始化）时，**按下面步骤把整套开发规范建好**，并引导用户补资料；建好后日常按 §2 使用。
> **判据（是否已初始化）**：检查项目根是否有 `AGENTS.md`、`docs/DEVELOPMENT.md`、`docs/CAPABILITY_INDEX.md`、`SESSION_LOG.md`。都没有 → 执行 §1；已有一半 → 补齐缺的。

---

## 1. 初始化（未初始化时执行，先问用户后建文件）

### 1a. 在对话框中一次问清「占位资料」（别一次全问，合并成一组问题）
项目名｜一句话定位｜主要语言/运行时｜输入与测试命令｜核心架构（分层？一层？）｜外部依赖隔离规则（如 SDK 唯一入口）｜通信方式（总线 / 直接调用）｜是否已有事件机制。

### 1b. 创建 `AGENTS.md`（精简总纲，按回答填）
```md
# AGENTS.md — {项目名} 开发规则（总纲）
> 规则分两层：本文件=总纲；docs/DEVELOPMENT.md=详细规范；SESSION_LOG.md=进度。
> 强制：新会话只读 AGENTS.md + SESSION_LOG.md；其它文档按 §6 按需读。
## 1 项目一句话 {一句话}
## 2 仓库导航（一行）{顶层目录职责}
## 3 常用命令（门禁） {BUILD_CMD} | {TEST_CMD} | {架构校验(如有)}
## 4 铁律（违反即失败）
1 {核心约束1（如：所有外部动作必经认证/门禁）}
2 {核心约束2（如：模块间仅经消息总线/事件）}
3 {外部依赖隔离（如：唯一可 import 外部 SDK 的点）}
4 文档同步（强制）：改任何代码文件→同步更新能力索引/职责/关系链等文档，与代码同提交
5 禁止裸 any / 吞异常
## 5 规范流程（详见 DEVELOPMENT §2）
① 定位→查 docs/CAPABILITY_INDEX.md（功能→锚点+别名，防 grep 误判）② 理解→HOOK_MAP+关系链+消息→确定插入位 ③ 实现→过门禁 ④ 收尾→更新文档→同提交
## 6 文档导航 {各文档+何时读}
## 7 会话约定 开始只读 AGENTS+SESSION_LOG；结束更新 SESSION_LOG
```

### 1c. 创建 `docs/DEVELOPMENT.md`（详细规范）
```md
# DEVELOPMENT — 开发规范（详细）
## 2 开发流程 SOP：①定位(CAPABILITY_INDEX)②理解(HOOK_MAP+关系链+消息)③小步实现④收尾强制更新文档(能力索引/职责/关系链/文件树/SESSION_LOG)并同提交
## 3 第一性原理：真相源第一（有状态实体先持久化，UI=投影/事件=增量）；状态可重建；先契约后实现；复用优先；先问为什么
## 5 代码质量：禁裸any(unknown收窄)；catch{}至少warn；Promise .catch；搜索优先先查索引再grep；修改优于新建
## 6 文档同步协议（强制）：改码必更文档（见 AGENTS §4）；映射=代码文件→职责登记、影响调用面→重生成关系链、新功能→能力索引、文件树→README、专项→对应文档；改哪条更新哪条防零碎
## 7 门禁：{BUILD_CMD} 0 | {TEST_CMD} 过 | 自检(无残留旧引用/无幽灵模块/文档已同步)
## 8 提交：feat:/fix:/refactor:/docs:/chore:/test:；中文意图；与文档同提交
```

### 1d. 创建 `docs/CAPABILITY_INDEX.md` + `docs/HOOK_MAP.md`（骨架，随开发填）
```md
# CAPABILITY_INDEX — 能力索引（功能→锚点+别名）
> 改功能前先查（含别名）判"是否已实现/在哪"，未命中不得直接造轮子；发现"代码已有但未收录"→补条目。
| 能力域 | 能力 | 别名 | 锚点(文件·函数) | 状态 | 怎么扩展 |
|---|---|---|---|---|---|
# HOOK_MAP — 接入点地图（新功能插哪/前·后）
> CAPABILITY_INDEX 判未实现后，从这里选合法接入点并定前后；优先扩展点(事件/注册)，不改核心主干。
| 接入点 | 位置 | 前/后 | 消息 | 例 |
```

### 1e. 创建 `SESSION_LOG.md`
```md
# SESSION_LOG — 会话交接
> 纪律：只留【当前状态+最近进度+开放决策+待办+关键教训】，细节以 git 为准，不堆积。
## 当前状态 {项目形态/门禁/文档体系一句话}
## 最近进度（里程碑，细节以 git 为准）| 会话 | 主题 | 结果 |
## 当前开放决策 / ## 待办 / ## 关键教训
```

### 1f. 创建主 skills（小猫支持即可用；不支持也当索引）
在 `skills/src/` 建源码（或从参考项目拷贝精炼）：`locate-capability`（改功能前定位）、`insert-hook`（接入点）、`dev-flow`（流程+文档同步）、`event-messaging`（事件/消息，若用事件）、`backend-flow`（业务流，若有）、`architecture-rule`（架构铁律）。每个 `skills/src/<name>/SKILL.md` = frontmatter（name/description 触发条件）+ 精炼要点 + 指向 docs；建后同步到 `.pi/skills/<name>/SKILL.md`（`cp -r skills/src/* .pi/skills/`，pi 官方发现路径）。

### 1g. 初始化完成后向用户确认 + 记录
「已建 AGENTS/DEVELOPMENT/索引/地图/SESSION_LOG/skills；请确认占位资料；之后按日常流程开发」。

## 2. 日常使用（已初始化后，LLM 照此）
**检索四连**（接到需求必走，不盲目 grep 判"无"）：
```
①定位 查 CAPABILITY_INDEX（功能→锚点+别名）→已实现?复用/扩展；未实现?
②理解 查 HOOK_MAP(插哪/前后) + 关系链/BACKEND_CODE_MAP + 业务流/消息 → 输出决策再动手
③实现 只改锚点+hook 局部，过门禁
④收尾 更新能力索引/职责/关系链/文件树/SESSION_LOG 与代码同提交
```
**改码必更文档映射**：改代码→职责登记 + 影响调用面→重生成关系链 + 新功能→能力索引 + 文件树→README + SESSION_LOG。
**文档纪律**：简洁分层（AGENTS 一页总纲 + 详细 in docs）；改哪条更新哪条防零碎；过时即弃以 git 为准；从代码出发（JSDoc/AST）可持续复核。
**防误读过时**：读到描述旧模块/旧端口/旧命令的文档→先交叉代码（运行时>调用>测试>文档）确认；引用已删/旧结构的文档直接归档或标 ⚠️ 已过时（勿采信），勿当作依据。
