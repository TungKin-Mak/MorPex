## 2. 开发流程 SOP
```
① 定位：新增/改功能 → 查 CAPABILITY_INDEX（功能→锚点+别名+状态）
     已实现→复用/扩展；未实现→查 HOOK_MAP（插哪/前后）。禁止仅凭 grep 判"无"
② 理解：锚点函数关系链 + 业务流/消息（对应文档）→ 确定插入位与消息传递
③ 实现（小步）：只改锚点+hook，过门禁
④ 收尾（强制，同提交）：更新 CAPABILITY_INDEX / 职责/文件注册 / 影响调用面重生成关系链 / 文件树 / SESSION_LOG
```

## 3. 编程第一性原理
1. 真相源第一：有状态实体先确立持久化真相源（UI=投影、事件=增量、内存=视角）。
2. 状态是数据可重建；请求/视图要能从真相源恢复。
3. 先契约后实现（TS 接口先定，读写共用）。
4. 复用优先（复用既有真相源/能力，不新建）。
5. 先问为什么：答「真相源/生命周期/谁写谁读」再动手。

## 5. 代码质量
| 项 | 要求 |
|---|---|
| `any` 裸 | 禁止（外部无类型除外），用 unknown 收窄 |
| 吞异常 | `catch{}` 至少 console.warn |
| Promise | `.catch(err=>console.warn(...))` |
| 文件 | 搜索优先（先查索引后 grep）；修改优于新建；.js 后缀；行数>800 考虑拆 |
| 反模式 | 幽灵模块→接入/删；别名壳→删；未实例化条件→构造实例化 |

## 6. 文档同步协议（强制）
> **改任意代码文件 = 必更新相应文档**；无对应文档须在提交信息注明"文档不涉及（原因）"。

| 改动 | 必更文档 |
|---|---|
| ★改代码文件 | 文件职责/注册（FILE_REGISTRY 类）必更 |
| 影响函数/调用/文件结构 | 重新生成关系链文档（BACKEND_CODE_MAP 类） |
| 新增/改造功能 | 能力索引（条目+状态+别名） |
| 文件树/目录 | README/架构文档的文件树 |
| 层/链/消息/配置/测试 | 对应专项文档（架构/流程/事件/配置/测试） |
| 任一功能 | SESSION_LOG |

原则：先人审后更新；文档随代码同提交；改哪条更新哪条（防零碎）；过时移 archive；新增文件先登记。
